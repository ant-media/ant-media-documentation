# H.264 Codec

**H.264** is the most widely supported video codec across browsers, devices, and hardware platforms. It is the default and most reliable choice for streaming in Ant Media Server.

For a comparison with other codecs, see [Video Codecs Overview](/guides/configuration-and-testing/video-codec/).

## What you'll accomplish

By the end of this guide, you will:

1. Understand when H.264 is the right codec for your use case.
2. Enable H.264 from application settings in the web panel.
3. Know how H.264 behaves in SFU and adaptive bitrate (ABR) modes.
4. Combine H.264 with VP8 when you need broader WebRTC browser coverage.

## Why use H.264?

| Benefit | Details |
|---------|---------|
| Universal compatibility | Supported by Chrome, Safari, Firefox, Edge, and most mobile and embedded devices. |
| Hardware acceleration | Most devices support H.264 encode/decode in hardware, reducing CPU load and latency. |
| Low latency | Well suited for real-time **WebRTC** streaming. |
| Stable performance | Mature, widely deployed standard across live streaming workflows. |

:::info
Ant Media Server uses **libopenh264** for software-based H.264 encoding and supports **h264_nvenc** for hardware-accelerated encoding on NVIDIA GPUs.
:::

## When to use H.264

Choose H.264 when you need:

- **Broad compatibility** across browsers, devices, and platforms.
- **WebRTC-based** real-time streaming with predictable performance.
- **Stable, low-latency** delivery for live applications.
- Support for **mobile, embedded, or low-powered** clients.
- **Hardware-accelerated** encoding and decoding where available.

H.264 is the recommended starting codec for most Ant Media Server deployments.

## Protocol support

H.264 works across most Ant Media Server ingest and playback paths:

| Area | Support |
|------|---------|
| WebRTC | Yes |
| RTMP / RTMPS | Yes |
| SRT | Yes |
| WHIP | Yes |
| HLS / LL-HLS / DASH | Yes |
| MP4 recording | Yes |

## Step 1: Enable H.264

1. Log in to the Ant Media Server dashboard.
2. Select your application.
3. Open the **Settings** tab.
4. Enable **H.264** and save.

![h264](https://github.com/user-attachments/assets/cfe26a24-6b8e-4a5f-94d9-68bfc260fc47)

When only H.264 is enabled:

- **SFU mode:** Ant Media Server ingests H.264 streams and forwards them without transcoding.
- **Adaptive bitrate (ABR) mode:** The stream is transcoded into multiple H.264 bitrates so players can adapt to different network conditions and devices.

## Step 2: Enable H.264 and VP8 together (optional)

Some clients do not support H.264 in WebRTC. Enable **H.264** and **VP8** together when you need coverage across mixed browsers.

- **SFU mode:** Ant Media Server ingests WebRTC in H.264 or VP8; if both are available, **H.264 is prioritized**. The original stream is forwarded without transcoding.
- **ABR mode:** With at least one adaptive bitrate enabled, the stream is transcoded into multiple bitrates for both H.264 and VP8. See [Adaptive Bitrate Streaming](/guides/adaptive-bitrate/adaptive-bitrate-streaming/) for details.

## Streaming and playback

Almost all supported publish protocols accept H.264, including **WebRTC**, **RTMP**, **SRT**, and **WHIP**.
