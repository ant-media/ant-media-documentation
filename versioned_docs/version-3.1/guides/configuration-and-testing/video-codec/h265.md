# H.265 (HEVC) Codec

**H.265 (HEVC — High Efficiency Video Coding)** delivers similar video quality at lower bitrates than H.264, making it well suited for bandwidth-sensitive **HLS**, **LL-HLS**, and **DASH** workflows.

For a comparison with other codecs, see [Video Codecs Overview](/guides/configuration-and-testing/video-codec/).

## What you'll accomplish

By the end of this guide, you will:

1. Understand when H.265 is the right codec for your use case.
2. Enable H.265 from application settings in the web panel.
3. Publish H.265 streams over supported ingest protocols.
4. Configure **H.265 + H.264 with ABR** for browser-friendly playback.

## Limitations

| Limitation | Details |
|------------|---------|
| WebRTC | H.265 is not officially supported for WebRTC in most browsers. |
| Licensing | H.265 is not royalty-free and may require licensing fees. |
| Device support | Playback often depends on compatible hardware, OS, or media players. |
| Browser playback | Most browsers do not play H.265 directly; use H.264 transcoding for web clients. |

## When to use H.265

Choose H.265 when you need:

- **Lower bandwidth** for HD, Full HD, or 4K delivery over **HLS**, **LL-HLS**, or **DASH**.
- **Better compression efficiency** than H.264 at the same visual quality.
- **Reduced storage** for recordings and archived content.
- Ingest from **Enhanced RTMP**, **SRT**, or **RTSP** with H.265 video.

Keep **H.264 enabled** alongside H.265 when browsers or WebRTC clients must play the stream—use adaptive bitrate (ABR) to transcode H.265 to H.264 for those clients.

## Protocol support

| Area | Support |
|------|---------|
| WebRTC | No (not official in most browsers) |
| Enhanced RTMP | Yes |
| SRT | Yes |
| RTSP | Yes |
| HLS / LL-HLS / DASH playback | Yes (compatible clients) |
| H.264 fallback via ABR | Yes (recommended for browsers) |

## Step 1: Enable H.265

H.265 is **disabled by default**.

**Ant Media Server v3.0.1+:** enable H.265 from **Application → Settings** in the web panel.

**v2.17 and earlier:** enable H.265 from **Advanced settings** (`h265Enabled: true`).

1. Log in to the Ant Media Server dashboard.
2. Select your application (for example, `live`).
3. Open the **Settings** tab (use **Advanced** on older versions).
4. Set **`h265Enabled`** to **`true`** and save.

![H.265](https://github.com/user-attachments/assets/86376db8-21d7-4273-9b60-a267a013e8bf)

Example Advanced settings when H.265 is the only accepted ingest codec:

```properties
h264Enabled=false
vp8Enabled=false
h265Enabled=true
```

If H.264 and VP8 remain enabled, Ant Media Server accepts streams in any combination of those codecs plus H.265.

Other H.265-related properties can be adjusted from Advanced settings.

## Step 2: Publish H.265 streams

Supported ingest paths include **Enhanced RTMP**, **SRT**, and **RTSP**.

Use a tool such as **OBS** to publish an RTMP stream with H.265 video. See [Enhanced RTMP](/guides/publish-live-stream/rtmp/enhanced-rtmp/) for configuration details.

## Step 3: Play H.265 streams

| Client | Playback |
|--------|----------|
| Android | Native H.265 via **HLS**, **LL-HLS**, and **DASH** on most devices |
| Desktop | **VLC** and other third-party players |
| Browsers | Limited H.265 support; prefer H.264 transcoding for web playback |

Verify browser support: [caniuse.com — H.265](https://caniuse.com/?search=H.265)

## Step 4: Enable H.265 with H.264 and ABR (recommended for browsers)

Because browser and WebRTC support for H.265 is limited, enable **H.264** alongside H.265 and turn on **adaptive bitrate (ABR)** so Ant Media Server can transcode H.265 to H.264 for compatible clients.

:::info
At least one adaptive bitrate must be enabled. Without ABR, Ant Media Server will not transcode H.265 streams to H.264, and playback will fail on clients that do not support H.265.
:::

Example settings:

```properties
h264Enabled=true
h265Enabled=true
```

Enable at least one adaptive bitrate in your application. See [Adaptive Bitrate Streaming](/guides/adaptive-bitrate/adaptive-bitrate-streaming/) for details.
